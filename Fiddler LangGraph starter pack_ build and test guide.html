Fiddler LangGraph starter pack

An implementation plan for a starter pack that gives every LangGraph agent Fiddler tracing without the agent’s code knowing about Fiddler, plus step-by-step tests for a new demo agent and an existing agent.

SDK fiddler-langgraph 1.8.0 Python 3.11+ LangGraph 1.x LLM AWS Bedrock Package agent-starter 0.1.0
Bootstrap packagePins the Fiddler SDK, reads settings from env vars, instruments LangGraph.
TemplateReady project for new agents. The customer edits one file.
Launcheragent-starter-run traces an existing agent with no code edits.

Part 1: build the starter pack

Do this once, on your side. Every file below is also in the fiddler-agent-starter.zip that came with this guide, so you can unzip it instead of copying by hand. Open a file to see its full contents.

  3. Write the bootstrap

    This is the core of the starter pack. init_fiddler() loads .env, checks the three required settings, creates the FiddlerClient, and calls LangGraphInstrumentor(client).instrument(). If anything is missing it prints a clear message and lets the agent run untraced, so a customer without Fiddler credentials is never blocked.

    src/agent_starter/config.pySettings from environment variables
    """Reads Fiddler settings from environment variables."""

import os
from dataclasses import dataclass

REQUIRED_VARS = ("FIDDLER_API_KEY", "FIDDLER_APPLICATION_ID", "FIDDLER_URL")


@dataclass(frozen=True)
class FiddlerSettings:
    api_key: str
    application_id: str
    url: str
    console_tracer: bool


def _truthy(value: str | None) -> bool:
    return (value or "").strip().lower() in ("1", "true", "yes", "on")


def tracing_disabled() -> bool:
    return _truthy(os.getenv("AGENT_STARTER_DISABLE"))


def load_settings() -> tuple[FiddlerSettings | None, list[str]]:
    """Returns (settings, missing_vars). settings is None if anything is missing."""
    missing = [name for name in REQUIRED_VARS if not os.getenv(name, "").strip()]
    if missing:
        return None, missing
    return (
        FiddlerSettings(
            api_key=os.environ["FIDDLER_API_KEY"].strip(),
            application_id=os.environ["FIDDLER_APPLICATION_ID"].strip(),
            url=os.environ["FIDDLER_URL"].strip().rstrip("/"),
            console_tracer=_truthy(os.getenv("FIDDLER_CONSOLE_TRACER")),
        ),
        [],
    )
    src/agent_starter/bootstrap.pyCreates the client and instruments LangGraph
    """Turns on Fiddler tracing for LangGraph. Safe to call more than once."""

import atexit
import os
import sys

from dotenv import load_dotenv

from agent_starter.config import load_settings, tracing_disabled

_initialized = False
_client = None


def _say(message: str) -> None:
    print(f"[agent-starter] {message}", file=sys.stderr, flush=True)


def _flush_on_exit() -> None:
    if _client is None:
        return
    try:
        _client.force_flush()
    except Exception as exc:  # never crash the agent because of tracing
        _say(f"Could not flush traces on exit: {exc}")


def init_fiddler(env_file: str | None = None):
    """Loads .env, creates the Fiddler client and instruments LangGraph.

    Returns the FiddlerClient, or None when tracing is off. The agent keeps
    running either way: missing settings only turn tracing off.
    """
    global _initialized, _client
    if _initialized:
        return _client
    _initialized = True

    # Values already set in the shell win over the .env file.
    load_dotenv(env_file or os.path.join(os.getcwd(), ".env"), override=False)

    if tracing_disabled():
        _say("Fiddler tracing is OFF (AGENT_STARTER_DISABLE is set).")
        return None

    settings, missing = load_settings()
    if settings is None:
        _say("Fiddler tracing is OFF. Missing: " + ", ".join(missing))
        _say("Set them in .env or your shell to turn tracing on.")
        return None

    try:
        from fiddler_langgraph import FiddlerClient, LangGraphInstrumentor
    except ImportError as exc:
        _say(f"Fiddler tracing is OFF. fiddler-langgraph is not installed ({exc}).")
        return None

    try:
        _client = FiddlerClient(
            application_id=settings.application_id,
            api_key=settings.api_key,
            url=settings.url,
            console_tracer=settings.console_tracer,
        )
        LangGraphInstrumentor(_client).instrument()
    except Exception as exc:
        _client = None
        _say(f"Fiddler tracing is OFF. Setup failed: {exc}")
        return None

    atexit.register(_flush_on_exit)
    _say(f"Fiddler tracing is ON -> {settings.url} (app {settings.application_id})")
    return _client

  4. Add the two no-code-change entry points

    The launcher turns tracing on and then runs the customer’s script unchanged, the same pattern as OpenTelemetry’s opentelemetry-instrument. auto.py is the fallback for platforms where the run command can’t be changed: one import line turns tracing on. The launcher also has --check to confirm setup before running anything.

    src/agent_starter/launcher.pyagent-starter-run command
    """agent-starter-run: runs any Python agent with Fiddler tracing turned on.

    agent-starter-run python app.py [args...]
    agent-starter-run app.py [args...]
    agent-starter-run python -m my_package.main [args...]
    agent-starter-run --check
"""

import os
import runpy
import sys

from agent_starter.bootstrap import init_fiddler

USAGE = (
    "usage: agent-starter-run [python] SCRIPT.py [args...]\n"
    "       agent-starter-run [python] -m MODULE [args...]\n"
    "       agent-starter-run --check"
)


def _check() -> int:
    from dotenv import load_dotenv

    from agent_starter.config import REQUIRED_VARS

    load_dotenv(os.path.join(os.getcwd(), ".env"), override=False)
    ok = True
    print(f"Python: {sys.version.split()[0]}")
    try:
        import fiddler_langgraph

        print(f"fiddler-langgraph: {fiddler_langgraph.__version__}")
    except ImportError:
        print("fiddler-langgraph: NOT INSTALLED")
        ok = False
    for name in REQUIRED_VARS:
        present = bool(os.getenv(name, "").strip())
        print(f"{name}: {'set' if present else 'MISSING'}")
        ok = ok and present
    print("Ready" if ok else "Not ready: fix the items above")
    return 0 if ok else 1


def main() -> None:
    args = sys.argv[1:]
    if args and args[0] == "--check":
        sys.exit(_check())
    if args and os.path.basename(args[0]).startswith("python"):
        args = args[1:]  # allow "agent-starter-run python app.py"
    if not args or args[0] in ("-h", "--help"):
        print(USAGE)
        sys.exit(0 if args else 2)

    # Tracing must be on before the agent's code is imported.
    init_fiddler()

    if args[0] == "-m":
        if len(args) < 2:
            print(USAGE)
            sys.exit(2)
        module = args[1]
        sys.argv = [module] + args[2:]
        sys.path.insert(0, os.getcwd())
        runpy.run_module(module, run_name="__main__", alter_sys=True)
    else:
        script = args[0]
        if not os.path.isfile(script):
            print(f"agent-starter-run: file not found: {script}")
            sys.exit(2)
        sys.argv = args
        sys.path.insert(0, os.path.dirname(os.path.abspath(script)))
        runpy.run_path(script, run_name="__main__")


if __name__ == "__main__":
    main()

  5. Build the template with a demo agent

    run.py belongs to the starter pack and calls init_fiddler() before the agent is built. The customer only edits agent/graph.py, which must keep a build_agent() function. The demo is a small support assistant with two tools, so traces show LLM calls, tool calls and graph nodes.

    template/agent/graph.pyThe demo agent (customer edits this)
    """YOUR AGENT GOES HERE. This is the only file you need to edit.

Demo: a support assistant that can look up orders and do simple math.
Replace the tools, prompt and graph with your own. Keep a build_agent()
function that returns a compiled LangGraph graph.
"""

import os
from typing import Annotated, TypedDict

from langchain_core.messages import SystemMessage
from langchain_core.tools import tool
from langchain_aws import ChatBedrockConverse
from langgraph.graph import START, StateGraph
from langgraph.graph.message import add_messages
from langgraph.prebuilt import ToolNode, tools_condition

SYSTEM_PROMPT = SystemMessage(
    "You are a friendly support assistant. Use the tools when they help. "
    "Keep answers short."
)

# Any Bedrock model that supports tool use. Copy the ID from the Bedrock console.
DEFAULT_MODEL_ID = "us.anthropic.claude-haiku-4-5-20251001-v1:0"

FAKE_ORDERS = {"A100": "shipped", "A200": "processing", "A300": "delivered"}


@tool
def get_order_status(order_id: str) -> str:
    """Look up the status of an order by its ID, for example A100."""
    return FAKE_ORDERS.get(order_id.strip().upper(), "not found")


@tool
def add_numbers(a: float, b: float) -> float:
    """Add two numbers together."""
    return a + b


TOOLS = [get_order_status, add_numbers]


class State(TypedDict):
    messages: Annotated[list, add_messages]


def build_agent():
    # AWS credentials come from the standard chain: env vars, AWS_PROFILE, SSO or an IAM role.
    llm = ChatBedrockConverse(
        model=os.getenv("BEDROCK_MODEL_ID", DEFAULT_MODEL_ID),
        region_name=os.getenv("AWS_REGION", "us-east-1"),
        temperature=0,
    )
    llm_with_tools = llm.bind_tools(TOOLS)

    def call_model(state: State):
        return {"messages": [llm_with_tools.invoke([SYSTEM_PROMPT] + state["messages"])]}

    graph = StateGraph(State)
    graph.add_node("agent", call_model)
    graph.add_node("tools", ToolNode(TOOLS))
    graph.add_edge(START, "agent")
    graph.add_conditional_edges("agent", tools_condition)  # tool call? -> tools, else end
    graph.add_edge("tools", "agent")
    return graph.compile()
    template/run.pyEntry point (starter pack owns this)
    """Runs the agent with Fiddler tracing. Part of the starter pack: no need to edit.

    python run.py                          # runs two demo questions
    python run.py "Where is order A200?"   # asks your own question
"""

import sys
import uuid

from agent_starter import init_fiddler

init_fiddler()  # must run before the agent is built

from fiddler_langgraph import set_conversation_id  # noqa: E402

from agent.graph import build_agent  # noqa: E402

DEMO_QUESTIONS = [
    "What is the status of order A100?",
    "What is 21.5 plus 20.5?",
]


def main() -> None:
    agent = build_agent()
    set_conversation_id(str(uuid.uuid4()))  # groups this run's questions in Fiddler
    for question in sys.argv[1:] or DEMO_QUESTIONS:
        result = agent.invoke({"messages": [("user", question)]})
        print(f"\nQ: {question}\nA: {result['messages'][-1].text}")


if __name__ == "__main__":
    main()

  6. Add a plain agent for testing the existing-agent path

    A ticket triage agent with two graph nodes and no Fiddler code at all. If it shows up in Fiddler, the no-code-change path works.

    examples/existing-agent/app.pyExisting agent, no Fiddler code
    """An EXISTING agent with no Fiddler code in it.

Ticket triage: classifies a support ticket, then drafts a reply.
Used to show that the starter pack can trace an agent without editing it.
"""

import os
import sys
from typing import TypedDict

from langchain_aws import ChatBedrockConverse
from langgraph.graph import END, START, StateGraph

llm = ChatBedrockConverse(
    model=os.getenv("BEDROCK_MODEL_ID", "us.anthropic.claude-haiku-4-5-20251001-v1:0"),
    region_name=os.getenv("AWS_REGION", "us-east-1"),
    temperature=0,
)


class TicketState(TypedDict):
    ticket: str
    category: str
    reply: str


def classify(state: TicketState):
    response = llm.invoke(
        "Classify this support ticket with one word: billing, technical or general.\n\n"
        f"Ticket: {state['ticket']}"
    )
    return {"category": response.text.strip().lower()}


def draft_reply(state: TicketState):
    response = llm.invoke(
        f"Write a short, friendly reply to this {state['category']} support ticket.\n\n"
        f"Ticket: {state['ticket']}"
    )
    return {"reply": response.text}


graph = StateGraph(TicketState)
graph.add_node("classify", classify)
graph.add_node("draft_reply", draft_reply)
graph.add_edge(START, "classify")
graph.add_edge("classify", "draft_reply")
graph.add_edge("draft_reply", END)
app = graph.compile()


if __name__ == "__main__":
    ticket = " ".join(sys.argv[1:]) or "I was charged twice for my subscription this month."
    result = app.invoke({"ticket": ticket})
    print(f"Category: {result['category']}\n\nReply:\n{result['reply']}")

Part 2: test the starter pack

Before you start, have these ready: Python 3.11 or newer (python3 --version), a Fiddler application with its API key, application ID (a UUID) and instance URL, and AWS access to Amazon Bedrock for the demo LLM calls. Commands are for macOS and Linux; Windows equivalents are noted where they differ.

Bedrock setup. The demo uses Claude Haiku 4.5 on Bedrock through the cross-region inference profile us.anthropic.claude-haiku-4-5-20251001-v1:0. In the Bedrock console, make sure this model is enabled for your account in your region, and that your AWS identity is allowed bedrock:InvokeModel and bedrock:Converse. Any Bedrock model that supports tool use works: copy its model ID or inference profile ID into BEDROCK_MODEL_ID. For EU or APAC regions, use the matching eu. or apac. profile.

Check that your AWS credentials work before starting: aws sts get-caller-identity should print your account. With AWS SSO, run aws sso login --profile your-profile first.

Build the demo support agent from the template. Tracing is on from the first run.

  1. Get the starter pack

    Unzip fiddler-agent-starter.zip, or once it’s on GitHub, click “Use this template” and clone your copy. Then go into the template folder.

    unzip fiddler-agent-starter.zip
cd fiddler-agent-starter/template

    python3 -m venv .venv

  3. Install the starter pack and the Bedrock library

    For local testing, install the starter pack from the parent folder. This also installs the pinned Fiddler LangGraph SDK and LangGraph. The requirements file adds langchain-aws, which brings in boto3.

    pip install -e ..

  4. Fill in your settings

    cp .env.example .env

    Windows: copy .env.example .env. Open .env and set FIDDLER_API_KEY, FIDDLER_APPLICATION_ID, FIDDLER_URL and AWS_REGION. Keep the default BEDROCK_MODEL_ID or replace it.     agent-starter-run --check

  6. Run the demo agent

    Ask your own question with python run.py "Where is order A200?".

  7. Confirm the traces in Fiddler

    Open your application in Fiddler and look at its traces. Allow a minute for them to arrive. Each question is one trace with a LangGraph root span, the agent and tools nodes, the LLM calls, and the get_order_status or add_numbers tool call. Both questions from one run share a conversation ID.

  8. Check the safety net

    Comment out FIDDLER_API_KEY in .env and run python run.py again.

    Expect: Fiddler tracing is OFF. Missing: FIDDLER_API_KEY, and the agent still answers. Put the key back afterwards.

  9. Make it your own agent

    Change the tools, prompt and graph in agent/graph.py. As long as it keeps a build_agent() function that returns a compiled graph, tracing keeps working with no other changes. Set FIDDLER_CONSOLE_TRACER=false once you’re done testing.

If something goes wrong

What you seeLikely cause and fix
agent-starter-run: command not foundThe virtual environment isn’t active, or the starter pack isn’t installed in it. Activate .venv and rerun the install step.
pip says requires a different PythonThe SDK needs Python 3.11+. Create the venv with python3.11 -m venv .venv (or py -3.11 on Windows).
Fiddler tracing is OFF. Missing: …The named variables aren’t set. Check that .env is in the folder you run from, or export them in the shell.
Setup failed mentioning the application IDFIDDLER_APPLICATION_ID must be the application’s UUID from Fiddler, not its name.
Tracing is on but nothing appears in FiddlerWait a minute and refresh. Check FIDDLER_URL is your instance URL with https://, the API key is valid, and the network allows outbound HTTPS to it. Export errors print in the terminal.
Spans print locally but some nodes are missingTracing was turned on after the graph ran. With the launcher this can’t happen; with the import option, make sure import agent_starter.auto is the first line.
NoCredentialsError or Unable to locate credentialsboto3 found no AWS credentials. Set AWS_PROFILE (and run aws sso login for SSO profiles) or the access key variables. Confirm with aws sts get-caller-identity.
AccessDeniedException from BedrockThe model isn’t enabled for your account in that region, or your IAM identity lacks bedrock:InvokeModel. Enable the model in the Bedrock console and check the IAM policy.
ValidationException mentioning the model ID or on-demand throughputThe model ID doesn’t exist in that region, or the model must be called through an inference profile. Copy the exact ID from the Bedrock console into BEDROCK_MODEL_ID and check AWS_REGION matches it.
ExpiredTokenExceptionTemporary credentials expired. Run aws sso login again or refresh AWS_SESSION_TOKEN.

SDK calls in bootstrap.py follow the fiddler-langgraph 1.8.0 package: FiddlerClient(application_id, api_key, url), LangGraphInstrumentor(client).instrument() and set_conversation_id(). The demo agents call Bedrock through langchain-aws’s ChatBedrockConverse. If you pin a different version, check Fiddler’s LangGraph SDK guide for changes.
